# Reviewer-sensitivity Kaggle matrix

This directory contains the **reviewer-requested sensitivity/ablation workflow**. It complements, rather than replaces, `kaggle/reviewer_matrix`, which contains the 204 main-table runs.

## Public-source rule

Every `TRSO_Reviewer_Sensitivity_Session_XX_OneCell.py` clones the public repository by default:

```text
https://github.com/tydeptrai21042004/TRSO_GCREST.git
```

For the archival paper run, set `TRSO_GITHUB_COMMIT` to the exact release commit. Each session writes `source_provenance.json` and refuses to resume a ZIP produced from another commit unless explicitly overridden.

## Reviewer coverage

The sensitivity matrix contains **72 logical groups / 180 training runs** across **14 runtime-balanced Kaggle sessions**. The plan is generated by `sensitivity_protocol.py` and is stored in `reviewer_sensitivity_plan.json/.csv`.

| Reviewer request | Implemented study |
|---|---|
| R2-C2: broader reliability evidence | `full`, `no_crossfit` (w/o partition-consistency weighting), `no_sampling_variance`, `diagonal_only` on DTD/R18, DTD/R50, Flowers/ViT-B16 |
| R1-C3, R2-C1/C5: calibration amount/partition stability | 25/50/100% calibration and seeded-random partition draws |
| R1-C3, R2-C5: calibration batching | calibration-only batch-size sensitivity while the optimization batch size stays fixed |
| R2-C3, R3-C1/C2/C3: D0/D1 rule | Shannon/D1-only, harmonic, geometric, arithmetic rules |
| R2-C3: mode-count stress test | 0.5x, 1x, 2x R |
| R1-C5, R2-C3, R3-C4: controlled low-rank budget | LoRA ranks 1/2/4/8/16/32/64; post-processing selects closest budget and validation-ranked oracle |

`no_crossfit` is retained as the historical implementation flag. In the paper and response letter it should be described as **without partition-consistency weighting**, because the two calibration partitions are not statistically independent cross-fitting.

## Runtime safety

The old revision Sessions 18-21 bundled 36-42+ runs into single cells. This matrix instead packs whole logical groups into 14 sessions, each with a conservative T4 planning total of at most 480 minutes. The runner additionally uses an 11h50m hard guard, ZIP reserve, per-run timeout, rolling runtime correction, group-level archive checkpoints, and resume support.

## Run

1. Push this corrected repository to GitHub.
2. Optionally create an immutable release/Zenodo archive.
3. Set `TRSO_GITHUB_COMMIT=<release SHA>` in the Kaggle notebook environment.
4. Copy/run Sessions 01-14 with GPU + Internet enabled.
5. Download each result ZIP.
6. Attach all ZIPs to a merge notebook and run `TRSO_Reviewer_Sensitivity_Merge_Results.py`.

The merge is accepted only when all 180 expected runs exist and all sessions resolve to one Git commit.
